6) MIGRATION KE BAAD CHECK (read-only, Supabase SQL Editor)
-----------------------------------------------------------
-- naye columns aa gaye?
SELECT column_name FROM information_schema.columns
 WHERE table_name = 'purchase_bills'
   AND column_name IN ('entered_by_employee_id', 'entered_by_name');

-- aaj ka leave digest ka raw data (jo message me jaata hai):
SELECT e.name, lr.from_date, lr.to_date, c.name AS company
  FROM leave_requests lr
  JOIN employees e ON e.id = lr.employee_id
  JOIN companies c ON c.id = lr.company_id
 WHERE lr.status = 'Approved'
   AND lr.from_date <= CURRENT_DATE
   AND lr.to_date   >= CURRENT_DATE;

2) FIX KYA KIYA
---------------
- DB: "No GST" ab gst_rate_pct = 0 save hota hai (NULL nahi). 0 ka matlab 0% GST,
  is liye g_total_plus_gst = total_amount + round off — bilkul jo aapne entry me
  dekha tha. Generated column ko drop nahi kiya (warna P&L/report views ud jaate),
  sirf CHECK me 0 add kiya: 0, 2.5, 3, 4, 9.
- Purane galat bills bhi repair: created_at >= 2026-08-17 (GST picker wali date)
  aur gst_rate_pct NULL — unhe 0 kiya. Isse 170 jaisa har bill theek ho jayega.
  2026-08-17 se purane NULL bills ko chheda nahi (unka 5% historical default hai).
- bill_pass_register.total_amt sabhi purchase_bill rows ke liye
  purchase_bills.g_total_plus_gst se RE-SYNC kiya — Bill Payment / Party Ledger /
  P&L turant sahi ho jayenge. Payments / Credit-Debit note adjustments ko haath
  nahi lagaya. (Agar kisi bill ka inflated amount pe payment ho chuka hai to uska
